# 🐾 貓咪小屋

純前端的養貓小屋，零依賴、可離線、手機優先。首頁是貓咪小屋：客廳互動（摸摸、逗貓棒、鏟貓砂、拍照）、
學院排課測驗、能力象限、商店裝修、扭蛋、稱號、紀念日、節日活動。

貓咪像電子雞一樣過日子：飽食度、清潔度會隨真實時間下降（離線也會補算，最多 24 小時），
在客廳會自己走動、跳躍、舔腳、洗臉、伸懶腰、追尾巴、打盹、上廁所，
也會跑來討摸摸、叼禮物、抓地毯、吐毛球、盯著窗外蝴蝶等你回應。
每個動作都有自己的全身立繪（見下方「貓咪立繪」），並在「📊 屬性」頁有 **🐾 全身姿勢圖鑑**可以放大查看。
親手照護是放大貓咪的點擊小遊戲：🪮 梳毛、🛁 洗澡（搓泡泡→沖水→吹乾）、✂️ 剪指甲，
身上的部位會輪流亮起，要在倒數結束前點到；越點越快，每次成功照護等級 +1、倒數時間變短（最多 Lv.5）。
照顧不好會生病（感冒、腸胃炎、毛球症；感冒拖過 24 小時會發燒），要帶去診所餵藥或打針，生病時不能上學。

小屋裡的小遊戲：

- **🧩 貓咪邏輯謎題（數獨打工）**：玩法致敬 Oakever Games 的 **Meowdoku**（本專案為自行實作，未使用其程式或素材）
- **📚 學院測驗**：六大學科題庫是標準化 JSON（`quizzes/`），新增題目或學科不用改程式，格式見 [quizzes/README.md](quizzes/README.md)

## 邏輯謎題規則

1. 棋盤切成 N 個連通色塊，**每個色塊恰好 1 隻貓**
2. **每一列、每一行恰好 1 隻貓**
3. **兩隻貓不能相鄰**（含斜角）
4. 每一題都是**唯一解**，而且**純靠邏輯推導就能解完，不需要猜**

## 操作

| 動作 | 效果 |
|---|---|
| 點格子 | 依目前模式動作（`✕ 排除` 打叉／`🐱 放貓`） |
| 再點同一格 | 取消該記號 |
| 長按（手機）／右鍵（桌機） | 清除該格 |
| 鍵盤 | `方向鍵` 移動、`X` 打叉、`C` 放貓、`Backspace` 清除、`H` 提示 |

放貓時若違反規則會扣 1 條小魚乾（共 3 條）；小魚乾用完就結束這一局。

## 功能

- 三種尺寸：**5×5 簡單、7×7 普通、9×9 困難**
- **每日挑戰**：以日期為亂數種子，同一天所有人拿到同一題；完成會記錄連續天數
- **自動打叉**（可關）：放貓後自動把同列、同行、同色塊與周圍 8 格打叉
- **提示**：用純邏輯推理找出「色塊／列／行只剩一個位置」的下一步
- 復原、重來、計時、各尺寸最佳時間（存本機）
- 深色／淺色主題；PWA 可加到主畫面、離線可玩
- 進度自動存在本機，重新整理會接續同一局

## 題目怎麼來的（重點）

隨機切色塊幾乎不可能得到唯一解（實測 n=7、9 都是 0/30），所以 `engine.js` 用**建構式**生成：

1. 先取一個合法解答（排列且相鄰兩列欄位差 ≥ 2）
2. 列出**所有**其他合法擺法（n=9 有 5242 種；A002464 數列）
3. 逐一指派格子到相鄰色塊，**每一格都必須維持「唯一解」**（某色塊內出現 2 隻貓的擺法即被排除）
4. 全部格子指派完後，再用**精確解題器**複驗「解數 = 1」，並用**純邏輯解題器**確認不用猜

因此每一題都同時滿足「唯一解」與「純邏輯可解」，這兩點由程式保證，不是靠運氣。

## 如何新增學院題目

題庫在 `quizzes/`，一個學科一個 JSON 檔，改完不用動程式：

1. **加題目**：在對應學科檔（例如 `quizzes/science.json`）的 `questions` 陣列加一筆
2. **加學科**：新增 `quizzes/<id>.json`（檔名＝`id`），並把檔名加進 `quizzes/index.json` 的 `subjects`
3. **驗證**：`node tests/quiz.test.mjs`，全部通過才提交（格式錯誤的題庫在瀏覽器會被略過）

一題的最小格式：

```json
{
  "id": "science-015",
  "type": "choice",
  "prompt": "貓咪主要透過哪裡流汗？",
  "options": ["全身皮膚", "肉球", "耳朵", "舌頭"],
  "answer": 1,
  "tip": "可省略：作答後顯示的小提示",
  "explain": "貓的汗腺主要在肉球。"
}
```

- `id` 在學科內不可重複；`answer` 是正解在 `options` 的索引（從 0 開始）；`options` 2～4 個
- 學科檔的其他欄位（名稱、顏色、每次抽幾題 `roundSize` 等）與新增題型的方法，見 [quizzes/README.md](quizzes/README.md)

## 照護小遊戲（梳毛／洗澡／剪指甲）

按「🪮 梳毛」「🛁 洗澡」「✂️ 剪指甲」進小遊戲，過關會提升該項照護等級（`careLevels`），等級越高倒數越短。
三種照護的玩法刻意不同，而且每次進場的內容都會重抽，避免重複感：

| 照護 | 玩法 | 每場變化 |
|---|---|---|
| 梳毛 | **描**：照目標上的箭頭方向拖一段距離（↑↓←→ 每次隨機） | 隨機挑 3 個部位當重點、目標數 5～6、偶爾混進「毛球」（梳一下算 2 點） |
| 洗澡 ①搓泡泡 | **連點**：點亮起來的部位 | 部位隨機 3～4 個、貓會掙扎（點到不算） |
| 洗澡 ②沖水 | **按住**：壓住亮起的位置直到內圈縮到剛好 | 部位隨機 3 個、貓會掙扎 |
| 洗澡 ③吹乾 | **描**：照箭頭方向擦乾 | 部位隨機 3 個（含耳朵） |
| 剪指甲 | **放大鏡**：鏡頭對準貓掌，點亮起的爪尖 | 各品種腳掌位置見 `BREED_PAWS` |

- 中途放開（按住／描）不算數，目標會重新計時，並提示「要按住喔～」「順著箭頭拖～」。
- 描／擦要在 `.care-cat` 上拖曳，該容器已設 `touch-action: none`，手機上不會被當成捲動。
- 目標的顏色就是機制提示：淡藍＋箭頭＝描、淡藍＋內圈＝按住、橘色圓＝點。

## 可互動的貓（小屋）與數獨圖示是兩套

- **小屋可互動的貓只有 4 隻**：白貓（key `0`）、橘貓（`2`）、黑貓（`1`）、三花（`4`），
  定義在 `js/pet.js` 的 `INTERACTIVE_CATS`。每一隻都有 14 種全身姿勢立繪。
  臉圖示刻意挑與品種相符的（`icons/cats.webp` 第 0／2／1／4 張），
  所以數獨裡看到的臉跟小屋裡的貓是同一隻。
- 領養時從這 4 隻選 1；另外 3 隻在合作過關數達 **3／8／15 場**時解鎖，圖鑑上限就是 4 隻。
- 舊存檔若存著不在名單內的 key，載入時由 `normalizeCatKey()` 換算成同品種的那隻（好感度、稱號、紀念日都會延續）。
- **數獨「🐱 換貓」那 81 個貓臉圖示是另一套、跟這份名單無關**（`js/meowdoku.js` 的 `showSkinPicker`），
  仍可任選 81 張臉或「🎲 每隻都不同」；切換夥伴時預設會把數獨圖示同步成該隻貓的臉。

## 貓咪立繪（全身姿勢）

客廳立繪是 4 個品種 × 14 種姿勢的透明 PNG／WebP：

| 類別 | 姿勢 | 觸發時機 |
|---|---|---|
| 基本 | `idle` 坐著、`pet` 討摸摸、`play` 玩逗貓棒、`sleep` 打盹 | 主畫面互動、逗貓棒、休息、貓跳台、暖被桌 |
| 動作 | `walk` 走路、`run` 暴衝、`jump` 跳躍、`lick` 舔腳掌、`wash` 洗臉、`stretch` 伸懶腰、`tail` 追尾巴、`yawn` 打哈欠、`scratch` 磨爪爪、`eat` 吃飯飯 | 自主行為、事件（磨爪、蝴蝶、叼禮物）、餵食、照護完成 |

- 品種前綴：`cat`（白貓）、`orange`、`black`、`calico`，檔案為 `icons/room/<品種>_<姿勢>.webp`（PNG 為 `onerror` 後備）。
- 每個姿勢在 `js/room.js` 的 `POSE_HOLD_MS` 定義顯示時間，時間到會自動回到 `idle`；`sleep` 沒有設限所以會一直躺著。
- 「📊 屬性」頁最下方是 **🐾 全身姿勢圖鑑**（14 張縮圖，點一下可放大看）。

立繪怎麼來的（可重現）：

1. 在 Google AI Studio 的 Playground 用 **Nano Banana Pro（`gemini-3-pro-image`）**，1:1、2K、關閉 Grounding。
2. 每個姿勢都**附上該品種的 `idle` 立繪當參考圖**（image-to-image），prompt 明講「保留同一隻貓的外觀與畫風，只換姿勢」，並列出「純白背景、無陰影、無地板、無文字、全身入鏡」等限制。
3. 生成的 2048×2048 圖用 `tools/cut_cat_poses.py` 去背（邊緣洪水填充＋補封閉洞＋alpha 柔化）、裁切，再依品種 `idle` 立繪高度等比縮放，輸出 PNG 與 WebP：

```bash
python3 tools/cut_cat_poses.py --source <生圖目錄>   # 加 --check 只報表不寫檔
```

## 開發與測試

```bash
# 核心驗證（解的合法性、色塊連通、解題器與暴力解交叉比對、生成品質與效能）
node tests/engine.test.mjs 40

# 學院題庫格式驗證（所有 quizzes/*.json）
node tests/quiz.test.mjs

# 本機開遊戲（Service Worker 需要 http/https）
python3 -m http.server 8120
# 開 http://127.0.0.1:8120/
```

`tests/engine.test.mjs` 的檢查項目：

- 精確解題器與**暴力解**逐盤交叉比對（避免解題器寫錯卻悄悄放行）
- 合法解、色塊覆蓋與連通性
- 生成品質：唯一解率、純邏輯可解率、耗時（實測 5×5 約 1ms、7×7 約 16ms、9×9 約 1 秒）

## 檔案結構

```
index.html              # 畫面骨架：貓咪小屋首頁（#/）、邏輯謎題（#/meowdoku）
style.css               # 樣式
audio.js                # 音效與背景音樂
engine.js               # 謎題生成器／解題器（純函式，瀏覽器與 Node 共用）
gen-worker.js           # 背景執行緒生成謎題
js/main.js              # 進入點：畫面切換、全域按鈕、啟動
js/ui.js                # 共用：DOM、儲存鍵、底部面板、提示音
js/pet.js               # 貓咪小屋：養成資料、客廳、圖鑑、稱號、紀念日、活動、分頁切換
js/room.js              # 客廳互動：立繪姿態、逗貓棒、貓砂盆、拍照
js/academy.js           # 學院測驗、能力象限、日常照護
js/life.js              # 電子雞生活：需求隨時間變化、生病與看醫生、自主行為、隨機事件
js/shop.js              # 商店與扭蛋
js/meowdoku.js          # 邏輯謎題畫面與操作
js/quiz.js              # 題庫格式定義、驗證、抽題、結算（純函式）
quizzes/                # 學科題庫 JSON（index.json 列出要載入的檔案）
icons/                  # 圖示、貓臉 sprite、客廳素材（含 4 品種 × 14 姿勢立繪）
tools/cut_cat_poses.py  # AI 生圖（Nano Banana Pro）→ 去背／裁切／縮放成遊戲素材

manifest.webmanifest    # PWA
tests/                  # engine.test.mjs、quiz.test.mjs
```
